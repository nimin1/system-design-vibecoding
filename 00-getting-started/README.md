## Why Bother?

You can write correct, well tested code that completely falls over when real users hit it. I've seen this happen within teams.

System design is about the decisions that determine whether your software works under real conditions: actual traffic, actual data volumes, actual failures. Code quality matters, but it's not the whole picture.

---

## If You Are Using AI Tools

AI code generators are good at syntax and implementation patterns. They are less good at knowing what to implement in the first place.

When you understand system design concepts, you can:
- Ask for specific architectural patterns by name
- Recognize when generated code is missing important pieces (error handling, caching strategies, etc.)
- Evaluate whether a suggested approach fits your actual requirements

This repo tries to connect each concept to how you would use it when prompting or reviewing AI generated code.
