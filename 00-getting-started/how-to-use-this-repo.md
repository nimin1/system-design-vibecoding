# How to Use This Repo

Some practical notes on working through this material.

---

## Approaches

**Sequential:** Start from Level 1 and work through in order. Each section builds on previous ones. This takes longer but builds a fuller picture.

**Reference:** Jump to whatever section is relevant to what you're working on. Each section tries to be self contained, though you might need to look up terms from earlier sections.

**Skim then deep-dive:** Read through everything quickly once, then go back and spend more time on the parts most relevant to you.

---

## Structure of Each Section

Most topics follow a similar structure:

| Section | What's there |
|---------|--------------|
| **What it is** | A straightforward explanation of the concept |
| **Why it matters** | When you would actually need this |
| **How it works** | The mechanics, with diagrams where helpful |
| **Trade-offs** | What you give up, what you gain |
| **Common mistakes** | Things that go wrong in practice |
| **AI prompting notes** | How to use this knowledge when prompting code generators |
| **Questions** | To check your understanding |

---

## Some Learning Suggestions

**Try to recall before looking at answers.** When there is a quiz question, actually try to answer it before expanding the answer. This is annoying but genuinely helps retention.

**Connect concepts to things you have built.** When you read about caching, think about places in your own code where caching would help (or where you have seen caching problems). This makes the concepts stick.

**Actually try the prompts.** The AI prompting suggestions aren't theoretical. Try them with whatever AI tool you use and see what comes out.

---

## What If You Already Know Some of This?

If you have experience with system design, you can probably skim the early sections quickly and slow down when you hit unfamiliar material.

The Foundation section (client-server, HTTP, databases) is genuinely basic. If you have built web applications, you likely know most of it.

The later sections (distributed systems, architectural patterns) tend to have more nuance even for experienced developers.

---

## Retention

Understanding these concepts once isn't the same as being able to apply them. What actually helps:

1. **Building things that use the concepts.** After reading about caching, add caching to a project.
2. **Reviewing with spaced repetition.** The flashcards are there for this.
3. **Explaining to someone else.** If you can explain CAP theorem to a colleague, you probably understand it.
