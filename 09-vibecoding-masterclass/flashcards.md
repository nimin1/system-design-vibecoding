# Level 9 Flashcards

Quick reference for AI-assisted development.

---

## Prompting

| Front | Back |
|-------|------|
| What makes prompts better? | Specific constraints, data model, technical requirements, non-functional requirements. |
| CARD framework? | Context, Architecture, Requirements, Details. |
| Why iterate prompts? | Easier to verify, more reliable for focused tasks. |

---

## Validation

| Front | Back |
|-------|------|
| Common API issues? | Wrong status codes, missing validation, no auth checks. |
| Common DB issues? | N+1 queries, missing indexes, no transactions. |
| Improve AI output? | Ask: "Edge cases?", "What could fail?", "Write tests." |

---

## Production

| Front | Back |
|-------|------|
| Your role? | Requirements, architecture, validation, security. |
| AI's role? | Implementation, boilerplate (with your guidance). |
| When write yourself? | Security-critical, performance-critical, complex logic. |

---

## Interviews

| Front | Back |
|-------|------|
| First step in interview? | Clarify requirements before designing. |
| Interview phases? | Requirements → Estimation → High-level → Deep dive → Wrap-up |
| Why explain thinking? | Interviewer evaluates thought process. |

---

## Prompting Patterns

| Front | Back |
|-------|------|
| Architecture prompt? | Requirements, constraints, tech stack, expected output. |
| Implementation prompt? | Context, requirements, error handling, testing. |
| Trade-off prompt? | Options, context, comparison criteria, recommendation. |

---

## Key Insight

| Front | Back |
|-------|------|
| Beginner to senior? | Learn concepts → Apply to prompts → Validate output → Design systems |
| Core differentiator? | System design knowledge guides AI, validates output, catches issues. |
